## 0. Коротко

1. **Инвариант «ключ не в рендере» (ADR #7, architecture §11) нарушен дважды.** Команда
   `secret_get` зарегистрирована и отдаёт значение секрета webview, а `hasApiKey()` реально тянет
   ключ в рендер при каждом старте HUD. Отдельно: `VITE_OPENROUTER_API_KEY` из `.env` компилируется
   в прод-бандл (`container.ts` не защищён `import.meta.env.DEV`). Оба фикса — часы, не дни. 🔴
2. **Надёжность стрима.** В `OpenRouterClient` нет ни connect-таймаута, ни таймаута до первого
   токена, ни idle-таймаута — «висящий» провайдер не вызывает failover, спасает только ручной Стоп.
   STT-таймаут 8 с фиксирован и не зависит от размера файла. 🔴
3. **Качество аудио-канала.** Нет гейта тишины: Whisper на тишине/шуме галлюцинирует текст, который
   промпт солвера считает «новее скриншота» → модель решает не ту задачу. 🔴
4. **Резидентное приложение без резидентных примитивов.** Нет трея, нет выхода, нет индикатора
   записи при скрытом HUD; дефолтные хоткеи `Ctrl+Alt+S/L/Enter` совпадают с JetBrains; вся
   конфигурация моделей — compile-time (`VITE_*`), любая настройка = пересборка. 🟠
5. **Приватность данных.** Скриншоты чужого/работодательского кода и голос собеседника уходят к
   произвольному провайдеру за OpenRouter без `provider.data_collection=deny`; история пишется в
   открытую SQLite без ретенции и без просмотра. 🟠
6. **Дрейф документации.** `architecture.md` описывает `ModelRouter`, `AgentRepository`, `sqlite-vec`,
   таблицу `agents`, событие `hotkey://triggered`; не описывает `llm_cancel`, `audio_*`, clipboard,
   маршруты. README упоминает «Vercel AI SDK + sqlite-vec». Для документа-«точки входа без истории
   чата» это критичнее, чем кажется. 🟠

Хорошая новость: архитектурный каркас (порты/DI/контракт/тесты, 246 TS + 75 Rust тестов, eval) —
в порядке; почти все находки локальные и не требуют перестройки.

## 1. Что сделано хорошо (сохранить)

- **Шов и слои держатся тулингом, а не дисциплиной**: `eslint no-restricted-imports` для `ui/*`,
  контейнер — единственное место с конкретными реализациями, use-cases тонкие.
- **Контракт стрима** (`text-delta* → finish | error{retryable}`) и `ResilientLlm` «до первого
  токена» — правильное место для failover; классификация ошибок в native, оркестрация в TS.

- **Защита от инъекций**: промпты трактуют скриншот/`<code_text>`/`<transcript>` как данные;
  `block()` нейтрализует закрывающий тег; `react-markdown` без `rehype-raw`; shiki отдаёт токены

- **Area-downscale в native**, prompt-cache breakpoint только для Anthropic, `pnpm models:check`,
  eval с судьёй и held-out кейсами — редкая для MVP зрелость.

## 2. Безопасность и приватность

### 2.1 🔴 `secret_get` отдаёт ключ в webview — secure-native фактически не работает

- **Где:** `src-tauri/src/lib.rs:90` регистрирует `commands::secrets::secret_get`
  (`src-tauri/src/commands/secrets.rs:7-13` — возвращает `value` любого ключа);
  `src/core/application/use-cases/manage-api-key.use-case.ts:19-22` → `secrets.get(...)` →
  `src/infrastructure/tauri/tauri-secrets.adapter.ts:14-18` → `invoke('secret_get')`;
  вызывается из `useApiKeySettings` при каждом монтировании HUD.
- **Что:** значение API-ключа проходит через IPC в JS-память при каждом старте (затем выбрасывается
  после проверки `length > 0`). Любой код в webview (XSS, скомпрометированная npm-зависимость —
  ровно та угроза, ради которой выбран secure-native) может в любой момент вызвать
  `invoke('secret_get', { request: { key: 'openrouter.api_key' } })` и получить ключ. Команды
  приложения в Tauri v2 разрешены webview по умолчанию (`build.rs` не объявляет `app_manifest`,
  ACL на них нет).
- **Почему важно:** это не «теоретически», а прямое противоречие ADR #7 и DoD фазы 2. Пункт
  чек-листа `docs/manual-testing.md:44` («только `secret_get`/`secret_set` IPC трогают ключ»)
  сам узаконивает утечку — ручная проверка его и не поймала.
- **Что сделать (≈1 ч):**
  1. Заменить `secret_get` на `secret_has(key) -> bool`; `SecretsPort.get` → `has`;
     `ManageApiKeyUseCase.hasApiKey()` через него. `secret_get` убрать из `generate_handler!`.
  2. В `secret_set`/`secret_has` принимать только ключи из белого списка
     (`openrouter.api_key`), чтобы webview не использовал keychain как произвольное хранилище.
  3. Добавить `secret_delete` (в `KeyringSecrets` уже есть `delete_credential`) — нужен для
     UI «удалить ключ» (см. §4.6).
  4. Переписать пункт DoD/чек-листа: «в devtools нет ни одного IPC-ответа со значением ключа».
- **Связь с планом:** не учтено ни в tasks.md, ни в decisions.md; блокирует честное закрытие DoD
  фазы 2.

### 2.2 🔴 `VITE_OPENROUTER_API_KEY` компилируется в прод-бандл

- **Где:** `src/bootstrap/container.ts:122-127` — `import.meta.env.VITE_OPENROUTER_API_KEY`
  читается в ветке «не Tauri», но **не** под `import.meta.env.DEV`; `vite.config.ts:34` —
  `sourcemap: true` для прод-сборки; `.env.example:6` предлагает держать ключ в `.env`
  (`README`: `cp .env.example .env`).
- **Что:** Vite подставляет `VITE_*` литералами на этапе сборки. Если в `.env` на машине сборки
  лежит реальный ключ, `pnpm tauri build` зашивает его строкой в `dist/assets/*.js` (и в `.map`),
  а `frontendDist` целиком попадает в бинарник. В рантайме Tauri-ветка его не использует — но
  строка в бандле уже есть.
- **Что сделать (≈20 мин):** обернуть dev-ветку `selectLlm` в `if (import.meta.env.DEV)`;
  в `.env.example` перенести ключ в `.env.development.local` (Vite грузит его только в dev);
  `sourcemap: false` (или `'hidden'` + исключить `.map` из `frontendDist`).
- **Связь с планом:** нет; относится к DoD фазы 2 («проверить, что webview не содержит ключ»).

### 2.3 🟠 Данные уходят к произвольному провайдеру без политики хранения

- **Связь с планом:** нет. Отдельно отмечу (без оценки): запись голоса собеседника без его

## 3. Надёжность и производительность

### 3.1 🔴 Нет таймаутов и watchdog до первого токена

- **Где:** `src-tauri/src/infra/openrouter_client.rs:23-27` (`reqwest::Client::new()` без
  таймаутов), `:43-49` (`send()` без лимита), `:80-100` (цикл чтения без idle-таймаута).
- **Что:** если провайдер принял соединение и молчит (типично при деградации), запрос висит
  бесконечно: ни ошибки, ни `retryable`, значит `ResilientLlm` **не делает failover** — ровно в
  сценарии «провайдер лежит», ради которого failover построен. Спасает только ручной Стоп.
- **Что сделать (≈2–3 ч, всё в native):** connect-timeout ≈10 с; **TTFT-watchdog** ≈20–30 с до
  первого `text-delta` → `Error{retryable:true}` (failover сработает, т.к. контента ещё нет);
  idle-gap между чанками ≈60 с → `Error{retryable:true}` (после контента UI покажет
  «Interrupted»). Значения — env `AI_HELPER_LLM_*` по образцу STT. Тест на `StreamState` уже
  изолирован, таймауты тестируются через `tokio::time::pause`.
- **Связь с планом:** нет. Это самый дешёвый прирост устойчивости на единицу кода.

### 3.2 🔴 STT: нет гейта тишины → галлюцинации Whisper попадают в промпт как «истина»

- **Где:** `src-tauri/src/commands/audio.rs:39-56` (пусто только при `samples.is_empty()`),
  `src-tauri/src/infra/audio.rs:106` (`rms()` используется лишь спайком),
  `src/core/domain/agents-catalog.ts:34-35` («transcript wins — it is more recent»).
- **Что:** loopback на тишине/музыке/уведомлениях даёт не пустой буфер, а шум; Whisper на таком
  входе известен галлюцинациями («Продолжение следует…», «Субтитры сделал…», «Thank you for
  watching»). Результат идёт в `<transcript>`, которому солвер обязан верить больше скриншота.
  Плюс сценарий «стоп записи = отправка» (`toggle-recording.ts:27-32`) при случайном двойном
  нажатии шлёт свежий кадр + пустой/мусорный транскрипт в модель — платный холостой запрос.
- **Что сделать (≈2–3 ч):** в `transcribe_audio` до аплоада — RMS/dBFS-гейт (порог ≈ −50 dBFS,
  env), обрезка тишины в начале/конце (меньше байт, быстрее STT), фильтр известных
  фраз-галлюцинаций; при пустом транскрипте **и** пустом буфере кадров — не отправлять, показать
  «запись пустая». Ключ проверять **до** `take_audio()` (`audio.rs:40-52` — сейчас при отсутствии
  ключа аудио уже слито и потеряно).
- **Связь с планом:** нет; усиливает фазу 9 и eval-решение по `VITE_AUTO_TRANSCRIBE` не затрагивает.

### 3.3 🟠 STT-таймаут не зависит от размера файла

- **Где:** `src-tauri/src/infra/stt_client.rs:78` (`DEFAULT_STT_TIMEOUT_MS = 8_000`),
  `:146-170` (3 попытки, каждая заново грузит ≈1.9 МБ за 60 с).
- **Что:** на медленном аплинке 1.9 МБ + инференс легко > 8 с → три одинаковых таймаута → аудио
  потеряно, хотя сервер был здоров. Комментарий в коде («whisper-turbo ≈ пара секунд») не учитывает
  время аплоада.
- **Что сделать:** таймаут = база + k·размер (например 8 с + 1 с/200 КБ), либо дефолт 20 с; при
  таймауте второй попытки — не повторять идентичный запрос, а сообщать.
- **Связь с планом:** нет.

### 3.4 🟠 Тяжёлые синхронные команды на главном потоке

- **Где:** `src-tauri/src/commands/capture.rs:10-15` (`fn capture_screen`, не `async`),
  `src-tauri/src/commands/audio.rs:29-32` (`audio_stop_capture` джойнит поток, до 200 мс
  ожидания события), `secrets.rs` (I/O в Credential Manager).
- **Что:** по документации Tauri v2 команды без `async` выполняются **на главном потоке**, если
  не помечены `#[tauri::command(async)]`. Захват WGC + BGRA→RGBA + area-downscale + PNG-кодирование
  кадра 2560×1440 — заметные десятки–сотни мс, в это время event loop (перетаскивание,
  show/hide, рендер) стоит. Пользователь мог воспринять это как «HUD на мгновение замирает при
  захвате». Проверить замером; фикс тривиален.
- **Что сделать (≈30 мин):** `#[tauri::command(async)]` для `capture_screen`,
  `audio_stop_capture`, `secret_*` (или `spawn_blocking` внутри). Оконные команды `overlay_*`
  оставить как есть — им нужен главный поток.
- **Связь с планом:** нет.

### 3.5 🟡 Картинки через IPC как base64-JSON

- **Что:** каждый `invoke` сериализует до 5 новых + до 5 реплеенных скриншотов (история) в JSON
  (десятки МБ строк), webview держит их в Zustand и в `<img>` data-URL; native при каждой попытке
  failover декодирует/ресайзит заново (известный принятый пункт). Работает, но это главный
  потребитель памяти/латентности webview.
- **Что сделать (пост-MVP, ≈1 день):** «хэндлы вместо байтов» — `capture_screen` возвращает
  `id` + миниатюру; буфер и история держат `id`; `llm_stream` получает `imageIds` и подставляет
  байты в native. Побочно закрывает «кэш даунскейла между попытками failover» из tasks.md
  (кэш живёт рядом с байтами) и убирает скриншоты из памяти webview вовсе.
- **Связь с планом:** «Качество/инфраструктура → кэш даунскейла» — поглощается этим пунктом.

## 4. UX / продукт

### 4.1 🟠 Нет трея, выхода и индикатора записи при скрытом HUD

- **Где:** `tauri.conf.json:24,27` (`skipTaskbar`, старт скрытым), `Hud.tsx` — ни «Выход», ни
  «Свернуть».
- **Что:** приложение резидентное, но завершить его можно только Alt+F4 по сфокусированному
  безрамочному окну или через Task Manager; при провале регистрации хоткеев единственный канал —
  баннер в HUD (стопгэп с фазы 0.3, так и остался). Если HUD скрыт тогглом во время записи —
  **ни одного индикатора**, что loopback-запись идёт (окно 60 с смягчает, но пользователь должен
  это видеть).
- **Что сделать (≈3–4 ч):** трей (`tauri` feature `tray-icon`): показать/скрыть, новый диалог,
  настройки, выход; иконка меняется при записи; ошибки регистрации хоткеев — в tooltip/уведомление.
  Опционально `tauri-plugin-autostart` — для always-on ассистента это ожидаемо.
- **Связь с планом:** в tasks.md трей упоминается только как «пока нет» в комментариях к фазам
  0.3/1; как задача не заведён.

### 4.2 🟠 Дефолтные хоткеи конфликтуют с JetBrains

- **Где:** `src/bootstrap/hotkeys.ts:26-51`.
- **Что:** в Windows-keymap IntelliJ/WebStorm/GoLand `Ctrl+Alt+S` = Settings,
  `Ctrl+Alt+L` = Reformat Code, `Ctrl+Alt+Enter` = Start New Line Before Current. Глобальная
  регистрация перехватывает их **системно**, пока AI-Helper запущен — IDE пользователя (профиль:
  TS/Go/NestJS) эти комбинации теряет. Комментарий в коде обходит только `Ctrl+Alt+V/C`.
- **Что сделать:** сменить дефолты на что-то вне IDE-кеймапов (например `Ctrl+Alt+Shift+…` или
  `Ctrl+F9…F12`) — минуты; и поднять приоритет бэклога «Настраиваемые хоткеи» (см. 4.3).
- **Связь с планом:** «Продукт/UX → Настраиваемые хоткеи в UI» — переоценить как 🟠, не бэклог.

### 4.3 🟠 Конфигурация моделей/маршрутов — compile-time

- **Где:** `src/bootstrap/model-chain.ts` (все `VITE_LIGHT_*`/`VITE_HEAVY_*`/`VITE_AUTO_TRANSCRIBE`/
  `VITE_*_ACCELERATOR`), в отличие от native `AI_HELPER_*`, читаемых в рантайме.
- **Что:** смена модели, температуры, reasoning, edge картинки, авто-транскрипции и хоткеев
  требует `pnpm tauri build`. При этом ровно эти параметры предстоит крутить по итогам eval
  («по eval решить: включать ли `VITE_AUTO_TRANSCRIBE`, какой heavy-профиль»). Env как механизм
  настройки десктоп-приложения — стопгэп, который пережил MVP.
- **Что сделать (≈1 день):** экран настроек в ⚙ поверх `tauri-plugin-store` (уже подключён, но
  не используется): хоткеи (запись комбинации нажатием), primary/fallbacks per route,
  temperature/reasoning/edge, auto-transcribe, окно записи, STT-язык/словарь, ретенция
  истории. Env/`AVAILABLE_MODELS` остаются дефолтами. `ResilientLlm` уже принимает профили
  конструктором — менять только composition root (+ пересоздание `ResilientLlm` при смене).
- **Связь с планом:** объединяет «Настраиваемые хоткеи», «Сохранение позиции окна» и неявно —
  все решения «по eval» в один экран.

### 4.4 🟠 Захват активного окна вместо/до «кропа области»

- **Что:** tasks.md хочет «кроп области/окна» (R17: тайлы отвергнуты, нужен UI выбора области).
  UI выбора области — DPI-ловушка (отмечена в `dto.ts`) и отдельный оверлей. **Захват окна под
  курсором / активного окна** даёт 80 % эффекта без UI: `scap` поддерживает `Target::Window`,
  foreground-окно известно ОС, DPI-пересчёт не нужен. IDE на части 2560-экрана после даунскейла
  до 1568 теряет мелкий шрифт; окно IDE целиком — нет.
- **Что сделать (≈0.5 дня):** режим захвата в настройках (экран под курсором / активное окно);
  `CaptureRequestDto.windowId?` или флаг `activeWindow`. Region-UI оставить пост-MVP.
- **Связь с планом:** «Продукт/UX → Кроп области / окна» — предлагаю расщепить: окно сейчас, область потом.

### 4.5 🟠 «Переспросить на heavy» — ручная эскалация одной кнопкой

- **Что:** ADR #8 отверг **автоматическую** эскалацию по «сложности» (субъективно, гадание) —
  согласен. Но ручная кнопка под ответом солвера «↑ Переспросить на heavy» не требует триггера:
  пользователь сам видит слабый ответ. Реализация — `askAndStream`/`analyzeAndStream` с
  `route: 'heavy'` для того же `sent`-промпта (он уже сохранён в `Dialog.turns`).
- **Связь с планом:** нет; не противоречит ADR #8.

### 4.6 🟡 Управление ключом и стоимостью

- «Проверить ключ» в ⚙ (`GET /api/v1/auth/key` отдаёт лимит/расход) — мгновенная обратная связь

- Счётчик стоимости за сессию под `RunInfoLine` + мягкий порог («> $1 за сессию») — данные
  уже есть в `finish.usage.cost`, это 20 строк в сторе.

### 4.7 🟡 Окно

- HUD центрируется на основном мониторе; при работе на втором мониторе кадр берётся «под

  первом `show()` (тот же `monitor_from_point`) + сохранять позицию (бэклог) — одна задача.
- Esc для Стопа работает только при фокусе на HUD; глобального «стоп» нет. Дешёвый вариант:
  SEND-хоткей при пустом буфере во время стрима = Стоп.
- Проверить вживую, что `overlay_show` не уводит фокус из IDE/звонка (`set_focus` вызывается
  только в single-instance колбэке — хорошо; поведение `show()` на Windows зависит от tao).

### 4.8 🟡 Язык интерфейса и подсказки

- Смесь EN/RU уже в списке; добавлю: текст-подсказки в `MessageList` («Press the hotkey…») не
  называет ни одной комбинации — при пяти хоткеях первый экран должен их показывать.

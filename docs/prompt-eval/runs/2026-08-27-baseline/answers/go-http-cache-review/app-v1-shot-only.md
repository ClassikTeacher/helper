Ревью: Go-приложение для работы с HTTP и кешированием

Critical

Строка 32 (json.Unmarshal): отсутствует проверка ошибки при десериализации JSON. Если b содержит некорректный JSON, ошибка игнорируется, и u останется с нулевыми значениями. Исправление: добавить проверку if err != nil { return name, err } после Unmarshal.
b, _ := ioutil.ReadAll(resp.Body)
var u User
err = json.Unmarshal(b, &u)
if err != nil {
    return name, err
}
Строка 27 (http11.Do): ошибка при выполнении HTTP-запроса игнорируется (_). Если запрос не удастся, код продолжит работу с нулевым resp, что приведёт к panic при попытке доступа к resp.Body. Исправление: проверить ошибку перед использованием resp.
resp, err := http11.Do(req)
if err != nil {
    return name, err
}
defer resp.Body.Close()
High

Строка 35 (проверка длины name): условие if len(name) > 10 обрезает строку индексом [10], что может привести к обрезанию многобайтовых UTF-8 символов и нарушению целостности данных. Исправление: использовать []rune для корректной работы с Unicode или явно указать кодировку.
if len(name) > 10 {
    name = string([]rune(name)[:10])
}
Строка 26 (baseURL конкатенация): строка baseURL конкатенируется напрямую с пользовательским ID без валидации. Это может привести к инъекции пути или неправильному формированию URL. Исправление: использовать url.JoinPath или fmt.Sprintf с экранированием.
req, _ := http.NewRequest("GET", fmt.Sprintf("%s/users/%s", baseURL, url.QueryEscape(id)), nil)
Medium

Строка 56 (cache[id]): доступ к map без синхронизации в многопоточной среде. Если handler вызывается одновременно из разных goroutine, возможна race condition. Исправление: использовать sync.RWMutex для защиты доступа к cache.

Строка 49-52 (обработка пустого ID): проверка if id == "" возвращает ошибку, но сообщение об ошибке жёстко закодировано. Лучше использовать именованные ошибки или константы. Исправление: определить константу const errMissingID = "missing id" и использовать её.

# `go-http-cache-review` — reviewer, эталон

**Агент:** `reviewer` · **Вход:** `source.go` (скриншот `shot-1.png`, опционально тот же код текстом в поле инструкций) · **Заведён:** 2026-08-27

Go-сервис: HTTP-хендлер с кэшем пользователей в `map` под `sync.RWMutex`. В 87 строках —
13 независимых дефектов, покрывающих все семь осей обхода из промпта ревьюера. Это
первый кейс набора R3 и якорь для всех правок промпта ревьюера.

Эталон получен от Claude Sonnet 5 (обычный чат, extended thinking, код текстом,
промпт «сделай ревью») — то есть это **достижимый** потолок, а не теоретический
максимум. Прогон приложения сравнивается с ним. Две находки (F3, F13) независимо
подтверждаются gopls на `source.go`, остальные проверены чтением.

## Эталонные находки (13)

Находка засчитывается по **сути**, а не по формулировке или severity. Severity
в таблице — ориентир для отдельной метрики (см. ниже).

| # | Severity | Якорь в коде | Суть |
|---|----------|--------------|------|
| F1 | Critical | `go func() { cache[id] = name }()` | Запись в `map` из горутины вообще без мьютекса. Это не recoverable panic, а `fatal error: concurrent map writes` — падает весь процесс. Плюс сама горутина здесь бессмысленна: операция дешёвая, выигрыша нет, только риск. |
| F2 | Critical | `cacheMu.RLock()` перед `cache[id] = name` | Блокировка на **чтение** удерживается над записью. Два запроса войдут под `RLock` параллельно и запишут в одну `map` одновременно → снова `concurrent map writes`. Нужен `Lock`. |
| F3 | Critical | `resp, _ := httpCli.Do(req)` | Ошибка `Do` игнорируется; при таймауте/DNS/недоступности `resp == nil`, и следующая же строка `defer resp.Body.Close()` даёт nil pointer dereference. |
| F4 | Critical | `req, _ :=` / `resp, _ :=` / `b, _ :=` / `_ = json.Unmarshal(...)` | Ни одна ошибка не проверяется, при этом сигнатура `FetchUser(id string) (string, error)` обещает ошибку и **всегда** возвращает `nil`. Контракт функции — фикция: вызывающий код доверяет `err` и получает пустое имя вместо диагностики. |
| F5 | High | `requests++` | Неатомарный инкремент глобального счётчика из конкурентных хендлеров — гонка (не паникующая, но теряющая инкременты). `atomic.AddInt64`, мьютекс, либо убрать: переменная нигде не читается. |
| F6 | High | `panic(err)` | Паника на пути обработки запроса. `net/http` её перехватит, но клиент получит пустой 500 без тела, в логах — стектрейс, формат ошибки неуправляем. |
| F7 | High | `http.Error(w, "missing id", http.StatusInternalServerError)` | Отсутствие обязательного параметра — ошибка клиента: 400 Bad Request, а не 500. |
| F8 | Medium | (отсутствует проверка `resp.StatusCode`) | Даже при успешной сети внешний API мог вернуть 404/500 с телом ошибки: оно спокойно распарсится в `User{}` с пустыми полями, и в кэш ляжет пустая строка как валидный ответ. |
| F9 | Medium | `name = name[:10]` | `len()` в Go считает байты, а не символы. Срез по индексу 10 разрежет многобайтовый UTF-8 символ (кириллица, эмодзи) пополам и даст невалидную строку. Нужно через `[]rune`. |
| F10 | Medium | `httpCli = &http.Client{}` | Клиент без `Timeout`: запрос к внешнему API может висеть вечно, вместе с ним висит хендлер и съедает горутину. |
| F11 | Medium | `http.ListenAndServe(":8080", nil)` | Сервер без `ReadTimeout` / `WriteTimeout` / `ReadHeaderTimeout` — уязвим к slowloris и медленным клиентам. |
| F12 | Medium | `cache = map[string]string{}` | Кэш без TTL и без ограничения размера. При долгой работе с большим числом уникальных `id` — неограниченный рост памяти, то есть утечка. |
| F13 | Medium | `ioutil.ReadAll(resp.Body)` | `io/ioutil` устарел с Go 1.16 — `io.ReadAll`. Отнесено к Medium (ось 6 «API contract and deprecations»), а не к Low: правило промпта «омитить Low при наличии Critical/High» иначе законно подавило бы эту находку. Засчитывается при любом заявленном severity. |

## Ловушки

- **Оси 5 (security) в коде нет.** `baseURL + "/users/" + id` иногда заявляют как
  «path injection». Это натяжка: `id` попадает в путь к своему же API, экранирование
  через `url.PathEscape` — законное улучшение, но не уязвимость. Считается **extra**,
  не false positive и не эталонной находкой. Если модель ставит этому Critical/High —
  это симптом того, что чек-лист заставляет что-то придумать под пустую ось.
- **`httpCli` часто читается со скриншота как `http11` / `httpC1i`.** Любое упоминание
  несуществующего идентификатора — объективный false positive и сигнал, что вход надо
  давать текстом (правка D промпта).
- **Номеров строк на скриншоте нет.** Любой номер строки в ответе — выдумка; см.
  метрику «валидность якоря».

## Метрики

Считаются вручную по ответу из `runs/<метка>/go-http-cache-review.md`.

| Метрика | Формула | Цель |
|---|---|---|
| **Recall** | `(полных + 0.5 × частичных) / 13` | ↑ главная |
| **False positives** | число утверждений, **фактически неверных** о коде (несуществующий идентификатор, приписанное поведение) | 0 |
| **Валидность якоря** | доля находок, чья цитата дословно встречается в `source.go` | → 1.0 (правка C) |
| **Точность severity** | доля полных находок, у которых severity совпадает с эталоном ±1 уровень | ↑ |
| **Extras** | защитимые находки вне списка (не штрафуются) | — |

**Частичная** находка — суть задета, но ключевой механизм не назван. Пример: «доступ
к `map` без синхронизации» без указания на горутину (F1) и без «`RLock` над записью»
(F2) — это 0.5, а не 2 находки.

**Правка промпта принимается**, если recall вырос и false positives не выросли.
